# Commissioning firmware executor

Build from the deployment directory with `sh firmware/build.sh`. The sketch targets Teensy 4.1 with the installed Teensy core 1.62.0 and QNEthernet 0.37.0. It compiles into a new `cartpole-teensy.*` directory under `TMPDIR` (or `/tmp`) and prints the artifact location. This command never connects to a board or flashes it. `sh tests/native/run.sh` exercises the same executor, framing, sketch, encoder I/O and pulse code on the host with AddressSanitizer and UndefinedBehaviorSanitizer.

The sketch uses native Ethernet on `192.168.50.2:9000`, static netmask `255.255.255.0`, no gateway, and USB CDC at a nominal 115200 baud. The private cable peer is `192.168.50.1`. This transport provides CRC integrity, no authentication. Do not expose this listener to the Internet. A single broker should own the control connection and distribute copied state to subscribers.

## GPIO, mechanics and observations

The working source's pinout is retained: cart STEP 2, DIR 3, Z STEP 4/6, shared active-low enable 8, AS5600 `0x36` on Wire1 SDA17/SCL16 at 400 kHz. Z direction pins 5/7 are initialized LOW. No code produces Z pulses; STEP4/6 are explicitly held LOW on every 7 microsecond pulse interrupt and disable. **GPIO8 energizes every connected driver, including Z. Physically secure the vertical mechanism before arming.** Z motion requires independently measured travel bounds and is unsupported. No limit switches or IMU are implemented or claimed.

The source-derived 7 microsecond DDS uses 200 motor steps, 16 microsteps, 60 pulley teeth and 2 mm GT2 pitch: 26666.666667 commanded steps/m. `cart_motion.h`, `cart_mechanics.h`, `encoder_reference.h` and `teensy_reference_store.h` are copied unchanged from the working Ethernet firmware. Motion commands reuse its jerk-limited governor with narrower local ceilings. DDS and encoder acquisition are derived from the same source rather than using its legacy parser or automatic controller.

Every `X`, `V` and `A` field describes commanded pulse position and governed command state. They are not independently measured carriage position, speed or acceleration. SDK observations use `position_source=commanded_steps`. Missed steps, belt slip, carriage movement while disabled and mechanical tracking error are undetectable. Stopping disables the shared drivers; it does not guarantee physical braking or position holding.

Theta is radians, zero upright, positive toward +x, with the working source's `ENC_INVERT=0`. The existing EEPROM `TCP1` record in bytes 0..7 supplies upright raw count when its magic/complement validate. Otherwise the source's fallback is 3953 counts from the 125 mm calibration. The startup sketch never overwrites EEPROM. This is a retained reference, not proof of current assembly calibration. Before hardware motion, verify theta near zero while held upright and verify its positive sign by leaning toward +x. If EEPROM is absent or wrong, calibrate using the original disabled-driver firmware's existing calibration facility before installing this executor, or deliberately change the compile-time fallback/reference polarity and rebuild. The deployment protocol has no reference-writing command. The nominal Python profile's raw-zero setting must be adapted to the measured reference when modelling raw encoder counts.

Raw 12-bit angle is read at each foreground 1 kHz control tick with magnet status checks. Invalid bus reads, missing magnet, weak/strong magnet status or failed fast-filter configuration clear encoder validity. Any such failure while armed faults immediately. Angle remains quantized in state; omega is a 30 Hz first-order filtered difference with wrap handling and is an estimate. AS5600 slow-filter configuration is set to SF=2x at boot, as in the working source.

## Explicit operator sequence

Boot initializes enable HIGH and every STEP LOW, without assigning a home or sending pulses. With the carriage physically at the measured rail center and Z secured, send `D1 home HALF_SPAN_M`. This asserts a manual coordinate reference, zeros commanded steps and leaves every driver disabled. Half-span must be 0.03..0.15 m. It is not an automatic home search.

Send `D1 arm SESSION` explicitly. Session is a nonzero uint32, distinct from the most recently used session; use a fresh random identity per arm. Arm requires valid home, a valid encoder sample no older than 3 ms and an allocated pulse timer. It enables the shared driver line at zero pulse rate. A first action must arrive before its 100 ms arm lease expires.

Read a fresh state and send `D1 act SESSION SEQUENCE OBSERVED_US TTL_MS KIND VALUE`. Sequence starts above zero and strictly increases without wrapping within a session. Kinds are `a` acceleration in m/s2, `v` velocity in m/s, and `x` position in m. The ceilings are 2 m/s2, 0.25 m/s and 20 m/s3. Position targets must fit inside half-span minus 15 mm. Out-of-range and nonfinite values are rejected, never silently clipped by the parser; accepted targets still pass through the rail/speed/acceleration/jerk governor.

The action lease expires at `OBSERVED_US + TTL_MS*1000`, not receive time. TTL is 10..100 ms. References must match an actual emitted state sample in the recent 64-timestamp ring, cannot be in the future and cannot already have expired. Both timestamps and expiry use wrap-safe uint32 microsecond comparisons. State reads and streaming do not renew motion. A passive client cannot enable by observing. This executor applies bounded motion intents; host policies remain responsible for renewed fresh actions.

`D1 stop` disables pulses/drivers and invalidates home and session. Faults do the same and remain latched, including after stop. `D1 clear` only resets a disabled/faulted executor; it cannot clear while active or make a failed timer available. Follow clear with a fresh manual home and explicit arm. No legacy motion, tuning, automatic restart, encoder-writing or Z commands are accepted.

## Framing and transport behavior

See [design.md](design.md) for the exact D1 request/state/info format. Each ASCII frame is `@PAYLOAD*HHHH\n`, CCITT-FALSE CRC16 (poly 0x1021, init 0xffff), maximum complete frame 256 bytes. CR, NUL, non-ASCII bytes, invalid CRC, oversize lines, unknown commands, extra tokens, invalid values and commands from another active owner fault active motion. Oversized input is discarded until newline, then reports an error. Passive malformed input reports an error without enabling anything.

The first valid arm owns either the single TCP connection or USB session. Other interfaces may read state/info; an action from the wrong owner faults. TCP disconnect/link loss or USB host disconnect during ownership faults immediately when detected. A second TCP client is rejected; a new TCP client is also rejected while USB owns active motion. TCP accepts no cached work after disconnect. Every transport consumes at most 128 input bytes and one complete frame per loop. Each transmitter writes at most 256 bytes per loop into available space; it never waits for a reader. Bounded 2048-byte output queues drop stream samples under congestion, and record drop counters internally. Failure to enqueue an active owner's command reply faults. Stream rate is 0..500 Hz, separate per interface; dropped samples cannot extend a motion lease.

The pulse ISR independently disables at the lease deadline and after more than 5 ms without a completed control heartbeat. It also prevents a pulse reaching either half-span minus 10 mm boundary. The normal governor reserves 15 mm. A late foreground control tick faults and does not catch up with a burst of updates. A pulse-side fault is harvested into the same latched executor state before commands are processed. These pulse-derived reserves are commissioning restrictions, not a validated physical safety guarantee.

An independent hardware inhibit, a defined power-up pull-up on enable, direct carriage feedback, verified wiring and supervised timing/tracking tests are prerequisites before unattended motion. The compile/native results in [firmware-validation.md](firmware-validation.md) do not establish them.
